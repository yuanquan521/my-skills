# Alembic Reference

Use this reference when adding migrations, configuring Alembic for async SQLAlchemy, or reviewing schema changes.

## Rules

- Use Alembic for every schema change.
- Do not call `Base.metadata.create_all(...)` from application startup code.
- Keep model discovery centralized through `app/db/base.py`.
- Run Alembic through `uv run` so it uses the locked project environment.
- Name migrations after the business change, not the table only.

## Required Files

- `alembic/env.py`
- `alembic/versions/`
- `alembic.ini`
- `app/db/base.py`

## `alembic/env.py` for Async SQLAlchemy

```python
from logging.config import fileConfig

from alembic import context
from sqlalchemy import pool
from sqlalchemy.engine import Connection
from sqlalchemy.ext.asyncio import async_engine_from_config

from app.core.config import get_settings
from app.db.base import Base


config = context.config

if config.config_file_name is not None:
    fileConfig(config.config_file_name)

target_metadata = Base.metadata


def get_url() -> str:
    return get_settings().database_url


def run_migrations_offline() -> None:
    context.configure(
        url=get_url(),
        target_metadata=target_metadata,
        literal_binds=True,
        dialect_opts={"paramstyle": "named"},
        compare_type=True,
    )

    with context.begin_transaction():
        context.run_migrations()


def do_run_migrations(connection: Connection) -> None:
    context.configure(
        connection=connection,
        target_metadata=target_metadata,
        compare_type=True,
    )

    with context.begin_transaction():
        context.run_migrations()


async def run_async_migrations() -> None:
    configuration = config.get_section(config.config_ini_section, {})
    configuration["sqlalchemy.url"] = get_url()
    connectable = async_engine_from_config(
        configuration,
        prefix="sqlalchemy.",
        poolclass=pool.NullPool,
    )

    async with connectable.connect() as connection:
        await connection.run_sync(do_run_migrations)

    await connectable.dispose()


def run_migrations_online() -> None:
    import asyncio

    asyncio.run(run_async_migrations())


if context.is_offline_mode():
    run_migrations_offline()
else:
    run_migrations_online()
```

## Commands

```bash
uv run alembic revision --autogenerate -m "create users table"
uv run alembic upgrade head
uv run alembic downgrade -1
uv run alembic current
uv run alembic history
```

## Migration Naming

Use concise action-oriented names:

- `create users table`
- `add order status`
- `index users email`
- `drop legacy sessions`

Avoid vague names like `update models`, `changes`, or `migration`.

## Review Checklist

- `target_metadata` points at `Base.metadata`.
- All new models are imported by `app/db/base.py` or a single metadata import location.
- Autogenerated migrations are reviewed before commit.
- Destructive changes are explicit and reversible when practical.
- New indexes and constraints have stable names when the database requires them.
- Application startup does not create tables.
